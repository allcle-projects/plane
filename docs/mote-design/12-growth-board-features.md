# 그로스 보드 기능 — 로드맵 (설계)

> 작성 2026-07-15. 대상: `plane.motemote.co.kr` (CE v1.3.1 fork, branch `mote`).
> 계기: otro가 그로스 업무(퍼널 이탈 분석 등)를 Figma 자유캔버스로 하고 있음을 확인(예시: [퍼널 이탈 분석 보드](https://www.figma.com/design/sowMWJX7L3wTWyhopFYT17/) — 스크린샷 12장+텍스트 주석 9개를 좌표로 자유배치). Notion/Miro/Figma 3개 도구를 Plane에 통합하고 싶다는 요청.
> 정본 관계: 이 문서는 기존 [`00-MASTER-ROADMAP.md`](./00-MASTER-ROADMAP.md)(24개 유료기능, mote.1~40 완료)와 **직교하는 별도 트랙**이다. 기존 로드맵은 "이슈 트래커 유료기능"이고, 이 문서는 "자유형식 협업 도구 흡수"다. 공수 표기·Phase 구조는 00 문서 관례를 따른다.

## 핵심 결론 (먼저 읽기)

1. **"AI가 잘 읽을 수 있는가"가 설계의 최우선 기준이다(otro 명시).** 이게 Notion/Miro/Figma를 그대로 흉내내면 안 되는 이유이기도 하다 — 자유 좌표 캔버스는 사람에게는 직관적이지만 AI에게는 "이 카드가 저 카드와 왜 가까이 있는지"를 좌표 근접도로 추론해야 하는 가장 나쁜 형태다. 실측: 위 Figma 예시 노드를 직접 읽어봤을 때, 스크린샷과 텍스트 주석의 대응관계가 좌표(`x`,`y`)로만 암시되어 있어 근접도 추론이 필요했다. 반대로 Plane 이슈(제목+본문+댓글+라벨)는 API로 필요한 필드만 뽑으면 되어 토큰 비용이 훨씬 낮다.
2. **자유 형식 문서는 이미 완성.** Wiki/Pages가 Tiptap 블록 에디터(mote.7, mote.31~33 Collections·Shared Pages·Publish Views까지 완료)라 Notion의 핵심 가치는 이미 있다. 신규 개발 불필요.
3. **테이블/DB 뷰는 80% 재사용 가능, 가장 빠르고 가치 큼.** Issue Views·Custom Fields·필터/그룹핑 엔진이 이미 있다. "테이블 뷰 타입 추가"만 얹으면 된다.
4. **캔버스·화이트보드는 신규 개발이지만, Miro를 복제하면 안 된다.** "자유배치 카드"이되 각 카드는 반드시 구조화 필드(제목·본문·라벨·연결된 이슈)를 갖는 **구조화 캔버스**로 설계한다 — 좌표는 사람의 시각적 정리를 위한 부가 메타데이터일 뿐, AI가 카드 내용을 읽을 때는 좌표 없이도 완결된 텍스트여야 한다.
5. **그래프뷰(백링크)는 우선순위를 올릴 만하다.** 페이지 간 링크가 명시적 DB 관계(PageLink 테이블)로 남으면, "이 문서가 왜 저 문서와 연결됐는지"를 AI가 좌표 추측 없이 바로 조회한다 — 오히려 캔버스보다 AI 판독성 이득이 크다.
6. **Figma는 계속 디자인 전용으로 남긴다.** 지금처럼 UX 리서치 낙서장(스크린샷+화살표+메모)으로 쓰는 용도는 공수 0으로 즉시 이전 가능하다 — 스크린샷을 이슈에 첨부(오늘 배포한 영상 첨부와 같은 파이프라인, 이미지는 원래 됐음), 코멘트로 설명, 라벨로 분류. 실제로 어제 세션의 GROWTH-126(퍼널 이탈 전수분석)도 이미 이 방식으로 Plane에 기록됐다.

## 4개 도구 역할 재정의

| 도구 | 계속 쓸 용도 | Plane으로 옮길 용도 |
|---|---|---|
| **Figma** | 실제 UI 디자인(컴포넌트·픽셀 단위) | UX 리서치 낙서장(스크린샷+주석) → 이슈+첨부+댓글로 |
| **Miro/FigJam** | (특수 브레인스토밍이 꼭 필요할 때만, 임베드로) | 그로스 기획 보드 → §2 구조화 캔버스로 |
| **Notion** | (계속 안 씀 권장) | 자유 문서 → 이미 Plane Wiki가 대체함 |
| **Plane** | 허브 — 모든 결과물의 최종 정본 | — |

## 항목별 공수 · 상태

| 항목 | 상태 | 공수 | 근거 |
|---|---|---|---|
| 자유 형식 문서 | ✅ 완료 | — | Wiki/Pages(mote.7)+Collections·Shared Pages·Publish Views(mote.31~33) |
| 테이블/DB 뷰 | 확장 가능 | **M** | Issue Views의 `display_properties`(JSONField)+필터엔진 기존. 뷰 타입 추가만 |
| 구조화 캔버스 | 신규 | **L** | 좌표 개념 자체가 없음(신규 모델). MVP는 카드 자유배치+줌만, 실시간협업·무한캔버스 제외 |

**공수 기호**: 00 문서와 동일 — S=1~2일, M=3~5일, L=1~2주, XL=2~4주.

## Phase 1 — 즉시, 공수 0 (otro 승인만 있으면 바로 적용)

Figma UX 리서치 낙서장 관행을 Plane 이슈 워크플로우로 전환:
- 스크린샷 → 이슈 첨부(이미지는 기존 기능, 영상은 오늘 mote.42/45로 배포 완료)
- 화살표+메모 → 코멘트로 설명(순서대로 여러 코멘트 달면 됨)
- 카테고리(배송지/결제/장바구니 등) → 라벨
- 근거: GROWTH-126이 이미 이 패턴으로 기록되어 있어 팀이 처음 쓰는 방식이 아님

## Phase 2 — 테이블/DB 뷰 (M, 1~2주)

- P1: `IssueView`에 `display_mode='table'` 추가, 기존 spreadsheet 레이아웃 컴포넌트 재사용
- P2: 컬럼 숨김/순서/정렬 저장(`display_properties` 확장)
- P3: CSV 내보내기(기존 importer 로직 역방향)
- MVP 제외: 인라인 셀 편집, 커스텀 집계 함수

## Phase 3 — 구조화 캔버스 (L, 2~3주)

- 데이터 모델: `Canvas`(workspace/project 스코프) + `CanvasCard`(x, y, width, height, **linked_issue_id 또는 title+body**, label)
- **AI 판독성 원칙**: `CanvasCard`는 좌표 없이도 독립적으로 의미가 통해야 한다 — 즉 카드 자체가 이슈이거나(연결), 최소 제목+본문을 가진 완결 텍스트여야 한다. 좌표만 있고 텍스트가 없는 카드(예: 순수 이미지+화살표)는 금지
- 프론트: 페이지 내 Tiptap 블록으로 임베드(`custom-canvas`, 오늘 만든 `custom-video` 패턴 재사용 — extension-config의 `group: "block", atom: true` 구조가 대형 인터랙티브 블록에도 적용 가능함을 이미 확인)
- MVP: 카드 자유배치+줌(20~200%)만. 실시간 협업·무한캔버스·그리드스냅 제외
- AI 조회 경로: 캔버스 API가 카드 목록을 좌표 없이(또는 좌표는 옵션 필드로) 순수 텍스트 배열로도 반환하도록 설계 → 토큰 비용 최소화

## Phase 4 — 화이트보드/마인드맵 (L~XL, 3~4주, 캔버스 이후)

- Phase 3의 `Canvas` 모델 확장: `CanvasEdge`(from_card, to_card, label) 추가
- 프론트 렌더러는 자체구현보다 오픈소스 검토 우선(excalidraw/tldraw — 현재 미설치, npm 추가 필요)
- **AI 판독성**: 엣지에 반드시 관계 설명 텍스트(label)를 요구 — "화살표만 있고 왜 연결됐는지 텍스트가 없는" 마인드맵 금지
- MVP 제외: 자동 레이아웃, 실시간 협업

## Phase 5 — 그래프뷰/백링크 (M~L, 2~3주, Phase 2와 독립적으로 병행 가능)

- `PageLink` 모델: `from_page`, `to_page`, `context_snippet`(링크 주변 텍스트, AI가 "왜 연결됐는지" 바로 읽게)
- 페이지 저장 시 `description_html`에서 `<a href="/pages/{id}">` 패턴 파싱 → PageLink 갱신
- 프론트: 그래프 렌더러(비추천: 순수 시각화 전용 라이브러리보다 "그래프+옆에 카드 리스트" 하이브리드 — 그래프는 사람용, 리스트는 AI 조회용)
- MVP: 노드 클릭 → 페이지 이동만. 필터·커스텀 레이아웃 알고리즘 제외
- **우선순위 메모**: 실사용 필요성이 아직 검증 안 됨 — Phase 2(테이블뷰) 배포 후 실사용 패턴을 보고 착수 여부 재확인 권장

## 권장 실행 순서

1. **Phase 1** (공수 0) — 지금 승인만 하면 적용, Figma 낙서장 관행 전환
2. **Phase 2 테이블/DB 뷰** (M) — 재사용률 최고, 그로스팀 최다 사용 빈도
3. **Phase 3 구조화 캔버스** (L) — Miro 대체, AI 판독성 원칙 지키며 신규
4. **Phase 5 그래프뷰** (M~L) — Phase 2 실사용 데이터 보고 착수 여부 결정, Phase 3과 순서 무관하게 병행 가능
5. **Phase 4 화이트보드/마인드맵** (L~XL) — 가장 마지막, Phase 3 인프라 재사용
